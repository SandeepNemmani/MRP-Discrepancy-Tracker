# MRP Discrepancy Detector

Find Bill-of-Materials (BOM) lines whose stated quantity-per-unit has
drifted from what actual consumption history shows, and price out the
purchasing exposure that drift creates before it turns into excess
inventory or a stockout.

## The problem

MRP (material requirements planning) systems generate purchase
requirements by multiplying each BOM line's quantity-per-unit against
forecasted demand. That math is only as good as the BOM configuration is. A superseded
revision, a unit-of-measure conversion error, or a part substitution
that never got updated in the BOM will get multiplied across every
unit forecasted, and the error compounds until someone
notices a shelf full of parts nobody needed, or a stockout on a part
nobody ordered enough of.

This is a generalized, synthetic-data version of a detection approach
I used in production planning to trace a set of BOM lines that were
inflating MRP-driven purchase requirements by about 57% over the
actual material consumption plan. Fixing them prevented potential
over-procurement worth $8.4M a year. No real company
data is used anywhere in this repo.

`sample_data/` is generated by `src/generate_sample_data.py` with a fixed random seed.

## Approach

1. **Roll up actual consumption.** For every parent SKU / component SKU
   pair, sum actual quantity consumed and parent units serviced across
   all available history, and divide to get a volume-weighted actual
   quantity-per-unit. Weighting by volume (rather than averaging period
   to period) keeps a handful of low-volume months from skewing the
   result.
2. **Compare against the BOM.** Join the actual QPU back to the BOM's
   stated QPU and compute the percentage deviation.
3. **Filter for signal, not noise.** Two guardrails keep the output
   focused: a deviation threshold (default 5%) so small, expected
   variance doesn't get flagged, and a minimum historical volume
   (default 500 parent units) so a pair with only a few transactions on
   record can't produce a false positive.
4. **Price the exposure.** For each flagged line, multiply the
   quantity-per-unit gap by next period's forecasted volume and unit
   cost. Over-statements become an over-procurement dollar figure;
   under-statements become stockout/emergency-buy risk.
5. **Report and visualize.** Output a full CSV sorted by dollar
   exposure, plus a bar chart of the top offenders.

## How to run

```bash
pip install -r requirements.txt

# regenerate the synthetic sample data (optional, already included)
python src/generate_sample_data.py

# run the detector
python src/mrp_discrepancy_detector.py \
    --bom sample_data/bom.csv \
    --consumption sample_data/actual_consumption.csv \
    --forecast sample_data/demand_forecast.csv \
    --threshold 0.05 \
    --min-units 500 \
    --output-dir output
```

Run the tests with:

```bash
pip install pytest
pytest tests/
```

deliberate error (23 lines) and keeps normal usage noise within
+/-3% per period, so every flag at the 5% threshold is a planted error.
This run's 23 flags against a known ground truth
is a way to sanity-check the detection logic itself, not a claim about
any real dataset.

## Tech stack

Python, pandas, NumPy, Matplotlib. No external services or APIs — runs
entirely on local CSVs.

## Possible extensions

- Track discrepancy history over multiple forecast cycles to catch
  drift trending in one direction before it crosses the threshold.
- Add a "confidence" score that weighs sample size alongside deviation
  size, instead of a single flat volume cutoff.
- Swap the CSV inputs for a live ERP/MRP connector (SAP, Oracle,
  NetSuite) and schedule the scan to run automatically each planning
  cycle.
- Break exposure down by commodity or supplier to route findings to
  the right buyer.
